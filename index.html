Personal Project

KnightFork — Runtime Exploitability Prioritizer

A side project that started because triaging security findings by hand was taking too long. It's a VS Code sidebar backed by 10 GitHub Copilot agents: you point it at a repo, it pulls findings from Dependabot, CodeQL, Wiz and an internal vulnerability dashboard, then ranks them by whether the vulnerable code is actually reachable and whether the infrastructure is exposed to the internet. You get a priority list, pick what to fix, and it opens the PR for you.

VS Code Extension (TypeScript) GitHub Copilot Agents Reachability Graph Terraform Exposure Scan GitHub / ServiceNow Automation

How it actually works

One orchestrator agent runs the whole pipeline. Separate "normalizer" agents each talk to one security source (Dependabot, CodeQL, Wiz, and an internal vulnerability dashboard) and convert its findings into a shared format. A reachability agent builds a call graph of the codebase so a finding only gets flagged as urgent if the vulnerable code is actually reachable from somewhere real, not just present in the repo. Another agent parses Terraform to check if the surrounding infrastructure is even exposed to the internet in the first place. All of that rolls up into a priority report, I pick what to fix, and a remediation agent groups findings by root cause, patches them, and hands off to an agent that opens the PR and files the change request. Each piece is its own agent so I can test and fix one stage without breaking the rest.

Data Platform

Iceberg / External Table Sync Fixes

Datasets would occasionally fail to sync between our internal data lake and Snowflake once they got big enough to hit a hard file-listing limit. Built a queue-based workaround that splits oversized refreshes into smaller chunks, plus a fix for notification wiring drifting out of config, both without needing to re-onboard the dataset from scratch.

SnowflakeAWS Glue / S3SQLDrift Detection

More detail

The sync job tries to list every file in a dataset's storage location in one go, and a handful of our biggest datasets have too many files for that to finish. Rather than refresh everything at once, I added a queue that tracks which parts of a dataset still need to sync, measures the size of each part first, and keeps splitting anything too large until every piece is safely small enough to refresh on its own. It's a deliberate, temporary workaround with a clear removal plan, not a permanent fixture, since the real fix depends on a platform-side limit being raised upstream.

AI Governance

Snowflake Cortex Governance & DCM Enablement

Not every team should get Cortex access by default, so I worked on a controlled way to turn it on or off per role, with an audit trail of who changed what. Also set up semantic views so Cortex Analyst can answer natural-language questions against real data, which is the groundwork Database Change Management (DCM) enablement builds on.

Snowflake CortexGovernanceSemantic ViewsCost Chargeback

More detail

Giving every team blanket access to an AI feature by default isn't great practice, so access is opt-in per team and fully reversible, with a record of who switched it on or off and when, which also feeds into usage-based cost tracking so AI spend gets charged to the right team instead of landing in one shared bucket. On top of access, I help set up the metadata layer that lets Cortex Analyst translate a plain-English question into the right query against a team's real data instead of guessing at table structure. Database Change Management (DCM), tracking and governing changes to database objects over time, is the next initiative that builds directly on this governance and semantic layer, and I'm currently helping scope what it covers.

Data Platform

Internal Data Marketplace

Helped build out our internal marketplace on top of Snowflake's Listings and Shares, so a dataset created once in one region can be picked up in another without copying any data. Also worked on the task graph that publishes and revokes these listings automatically.

Snowflake ListingsTask GraphCross-Region Data Sharing

More detail

Think of it like an internal app store for datasets. A team registers a dataset once, and other teams, even in a different cloud region, can discover it and "install" it into their own environment without anyone copying files around; it's really just a pointer to the same underlying data, so storage and governance stay in exactly one place. The publish and teardown steps run on a scheduled automation chain instead of someone manually granting access each time, and there's a health check that halts the chain if a step silently breaks, so a failure gets caught right away instead of turning into a confusing "why can't I see this dataset" ticket two days later. I also worked on the layer that resolves cross-region requests back to the right source account, and on curated, permission-scoped "views" of a dataset for consumers who shouldn't get the full thing.

Security

CI/CD Security Scanning (Wiz + CodeQL)

Got Wiz and CodeQL properly wired into our GitHub Actions pipelines, so results show up as normal GitHub security alerts instead of living in a separate dashboard nobody checks, and deployments won't go out if a scan fails.

WizCodeQLGitHub ActionsSARIF

More detail

Before this, scan results lived in their own separate dashboards, so someone had to remember to go check them. Now both tools report straight into the same security tab developers already see on a pull request, CodeQL runs on every push plus a daily schedule, and Wiz's checks are converted into a format GitHub understands and gated into the pipeline so a merge can be blocked if something serious turns up. It turned security scanning from an extra chore into something that just happens as part of shipping code.
